# 播放列表导入、缺失歌曲处理与依赖升级设计

## 状态

- 日期：2026-08-11
- 分支：`swt-java/v1.1.0`
- 状态：设计已确认，等待书面规格复核

## 背景

当前主窗口左侧只有歌曲表格。首次启动且数据库为空时会自动打开文件选择器，但列表加载后没有持续可见的添加入口。列表事件还把“选择变化”和“播放”耦合在一起，实际可能在单击时开始播放，与“双击播放”的界面语义不一致。

播放入口目前直接取得一条记录并尝试加载文件。文件被移动或删除后：

- 用户无法在双击时确认并清理失效记录；
- 上一首、下一首不会跳过失效记录；
- 播放器自然到达 EOF 后只复位界面，不会自动播放下一首；
- UI 只能观察 `playing()`，不能可靠区分自然结束、主动停止和播放异常。

项目依赖和 Maven 插件也存在一批稳定版更新。升级应与功能修改分组验证，避免一次性升级到预览版、里程碑版或不必要的新主版本。

## 目标

1. 在歌曲列表上方提供始终可见的添加歌曲按钮。
2. 单击只选择歌曲，双击才请求播放。
3. 双击的歌曲文件不存在时，询问是否只删除 SQLite 播放列表记录。
4. 上一首、下一首和自然播放结束时，按方向静默跳过不存在的文件。
5. 一轮扫描后仍找不到可播放文件时停止扫描并给出一次明确提示。
6. 只有当前播放会话自然到达 EOF 才能触发自动下一首。
7. 升级经过核实的稳定依赖和构建插件，并保留可单独回退的验证边界。
8. 更新 README 中的界面行为、依赖版本和验证结果。

## 非目标

- 不删除磁盘上的音频文件或歌词文件。
- 自动跳过缺失歌曲时不自动删除数据库记录。
- 不增加重复播放、随机播放或播放模式设置。
- 不引入完整 MVC、事件总线或第三方响应式框架。
- 不迁移到 JUnit 5、Hutool 6 或 SLF4J 2.1 Alpha。
- 不声称在当前 Windows 主机上完成 Linux 或 macOS 的 UI 运行验证。

## 方案选择

采用“小型播放导航逻辑 + 自然结束回调”。保留现有 SWT 主窗口、`Player` 抽象和 SQLite Wrapper，只拆分可以独立测试的导航决策，并让播放器明确报告自然 EOF。

没有采用只在 `MusicPlayer` 中根据 `!player.playing()` 推断结束原因的方案，因为该状态也可能由主动停止或异常造成。没有采用完整控制器重构，因为本次行为可以通过少量边界清晰的方法完成。

## UI 设计

### 列表区域

左侧列表容器从单控件填充布局改为一列布局：

1. 顶部是紧凑工具栏；
2. 下方歌曲表格占据全部剩余空间。

工具栏提供一个使用现有 `addMusic.png` 资源的图标按钮，悬停提示为“添加歌曲”。按钮不使用额外文字，不改变窗口的主要视觉风格。

点击按钮时打开现有 `SongChoose` 多选文件对话框。对话框关闭后重新查询数据库并刷新表格；用户取消时列表保持不变，不显示错误。

### 列表交互

- 单击：只更新表格选择项，不播放。
- 双击有效歌曲：播放该歌曲。
- 双击缺失歌曲：显示确认框“歌曲文件不存在，是否从播放列表删除？”
- 选择“是”：只按歌曲 ID 删除 SQLite `song` 表记录并刷新列表。
- 选择“否”或关闭对话框：不播放、不删除、不改变当前播放。
- 数据库删除失败：保留原记录，记录异常并显示简短错误提示。

刷新列表时按歌曲 ID 重新定位正在播放的记录并恢复高亮和 `PLAYING_INDEX`，而不是沿用可能已经变化的表格下标。若正在播放的记录被用户删除，则停止该播放并复位界面。

## 播放导航设计

移除含义混杂的 `next(String index, boolean next)` 调用方式，拆为三个清晰入口：

- 双击入口：只检查并播放用户明确选择的下标；文件缺失时弹删除确认框，不扫描其他歌曲。
- 相对导航入口：上一首使用步长 `-1`，下一首使用步长 `+1`。
- 自动完成入口：自然 EOF 后使用步长 `+1`，与下一首共用扫描逻辑。

在现有 `PlaylistNavigator` 中增加可测试的“查找下一条可播放记录”逻辑。算法规则如下：

1. 根据当前下标和方向计算第一个候选下标；没有当前歌曲时，向前从第一首开始，向后从最后一首开始。
2. 非空且可解析的路径使用 `Files.isRegularFile` 检查；空路径和非法路径统一视为缺失文件。
3. 文件不存在时继续按同一方向移动，并保留数据库记录。
4. 最多检查播放列表大小次，保证所有文件都缺失时不会无限循环。
5. 找到文件后更新当前歌曲和下标，再调用统一的实际播放方法。
6. 扫描一圈仍未找到时只显示一次“没有可播放的歌曲”。若当前仍在播放，则保持当前播放；若当前已经自然结束或本来就没有播放，则复位播放界面。

列表环绕行为保持不变：最后一首的下一首回到第一首，第一首的上一首回到最后一首。

## 自然结束通知

`Player` 增加单一自然完成监听入口，默认实现保持兼容；`SdlFftPlayer` 提供真实实现。监听器只表达“当前会话自然读到 EOF”，不把 SWT 类型引入播放器层。

`SdlFftPlayer.runPlayback` 使用局部布尔值记录是否读到 `-1`。清理时必须同时满足以下条件才通知监听器：

1. 音频输入确实返回 EOF；
2. 该 Session 仍能从当前 Session 容器中原子完成；
3. 不是 `stop()` 已经摘除的旧 Session；
4. 播放循环没有因异常或线程中断退出。

监听器运行在播放虚拟线程。`MusicPlayer` 维护单调递增的播放请求代次；双击、上一首和下一首等显式播放请求在检查文件或加载音频前先增加代次。自然完成监听器捕获当时的代次，再使用 `Display.asyncExec` 回到 SWT 线程。UI 回调只有在窗口未销毁、捕获代次仍等于当前代次且没有新歌曲正在播放时，才启动向前扫描。

代次校验覆盖“EOF 回调已经排队，随后用户又发起播放请求”的窗口。即使后续请求因文件缺失或加载失败而没有形成新 Session，旧回调也不能再推进播放列表。

主动切歌、上一首、下一首、退出、加载失败、设备异常和显式 `stop()` 都不会发出自然完成通知。

## 数据与错误边界

- 文件存在性检查只负责缺失文件决策；格式不支持或音频设备失败仍走现有 `MusicPlayerError` 提示，不自动删除记录。
- 删除条件只使用参数化的歌曲 ID，不接受 UI 传入表名、字段名或 SQL 片段。
- 自动跳过不写数据库，因此用户修复文件路径或恢复文件后，记录仍可见。
- 添加和删除后的列表查询、表格刷新、当前索引修正都在 SWT 线程执行。
- 播放完成回调不得直接访问 SWT 控件。
- 所有 UI 监听器捕获领域异常并显示提示，不允许异常逃出 SWT 事件循环。

## 测试策略

遵循先写失败测试再实现的顺序。

### 自动化测试

1. 向前扫描跳过一个或多个缺失文件。
2. 向后扫描跳过一个或多个缺失文件。
3. 扫描发生首尾环绕。
4. 全部文件缺失时最多检查列表大小次并返回空结果。
5. 空播放列表返回空结果。
6. 空路径和非法路径按缺失文件处理。
7. 播放器自然 EOF 只通知一次。
8. 主动停止、异常退出和被新 Session 替换的旧 Session 不通知自然完成。
9. 已排队的完成回调在播放请求代次变化后失效。
10. 删除歌曲只删除指定数据库 ID，不删除测试音频文件。
11. 添加或删除后按歌曲 ID 恢复当前下标。
12. 现有播放生命周期、SQL 参数化、歌词、进度和 PCM 测试继续通过。

### 构建验证

依赖分为“通用库”“JFace/SWT”“Maven 插件”三组升级，每组至少执行：

```powershell
mvn clean test
mvn clean package
```

最终在 Windows 上显式隔离并打包四个 SWT profile，避免本机自动激活的 `windows-x64` 混入外来平台：

```powershell
mvn -Pwindows-x64 clean package
mvn -P!windows-x64,linux-x64 -DskipTests clean package
mvn -P!windows-x64,macos-x64 -DskipTests clean package
mvn -P!windows-x64,macos-arm64 -DskipTests clean package
```

对每个包检查 Shade JAR 存在、主类清单正确、只包含目标平台 SWT 原生库。Windows 包进行 UI 冒烟检查；其他平台只声明交叉依赖解析与打包成功。

### 人工 UI 验收

1. 添加按钮可见、图标正确且工具提示可用。
2. 单击不播放，双击有效歌曲播放。
3. 双击缺失歌曲分别验证“是”“否”和关闭确认框。
4. 删除记录后磁盘文件不受影响，列表立即刷新。
5. 上一首、下一首分别跳过缺失文件并保持正确方向。
6. 自然播放结束后自动跳到下一首有效歌曲。
7. 全部歌曲缺失时没有死循环，只提示一次。
8. 播放中添加或删除记录后，当前歌曲高亮和导航顺序保持正确。

## 验收标准

- 添加歌曲入口始终位于歌曲列表上方，取消选择不会改变列表。
- 单击歌曲绝不触发播放，双击是唯一会弹缺失文件删除确认框的入口。
- 确认删除只移除 SQLite 记录，不删除任何音频或歌词文件。
- 上一首、下一首和自然 EOF 能按方向越过任意数量的缺失记录。
- 全缺失列表在有限步数内结束，不占用 SWT 线程持续循环。
- 旧 Session、主动停止和播放异常不会触发自动下一首。
- 全部自动化测试通过，Windows Shade 包可以启动。
- 四个平台 profile 独立打包，产物不混入其他平台 SWT 原生库。
- README 与最终实现、依赖版本和实际验证范围一致。
