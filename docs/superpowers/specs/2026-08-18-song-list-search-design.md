# 歌曲列表搜索框设计

## 背景

当前 MusicPlayer 的歌曲列表在主窗口左侧，通过 SWT `Table` 展示歌曲序号和歌曲名。列表数据由 `MusicPlayer.querySongs()` 从 SQLite 读取，再通过 `applyPlaylist(...)` 写入 `Constant.PLAYING_LIST`，双击、上一曲、下一曲都依赖这个可见列表索引。

用户希望在歌曲列表增加搜索框，用于快速定位歌曲。

## 目标

- 在歌曲列表区域增加搜索输入框。
- 搜索范围为歌曲名和歌手。
- 输入时实时过滤歌曲列表。
- 清空搜索词后恢复完整列表。
- 保持现有添加歌曲、双击播放、上一曲、下一曲、缺失歌曲删除等行为可用。

## 非目标

- 不改数据库结构。
- 不新增在线搜索能力。
- 不增加复杂排序、标签、拼音检索或模糊算法。
- 不重构播放器主窗口架构。

## 方案

采用内存过滤方案。主窗口维护一份从数据库读取的完整歌曲列表，搜索框内容变化时根据完整列表生成过滤结果，再复用现有列表渲染流程更新 SWT `Table` 和 `Constant.PLAYING_LIST`。

搜索框放在左侧歌曲列表上方工具栏中，位于“添加歌曲”按钮旁。提示文案为“搜索歌曲或歌手”。匹配规则为：

- 搜索词为空时返回完整歌曲列表。
- 歌曲名包含搜索词时匹配。
- 歌手包含搜索词时匹配。
- 匹配忽略大小写。
- 空字段按不匹配处理。

播放行为跟随当前可见列表。过滤后双击第 N 行播放过滤结果中的第 N 首；上一曲和下一曲在当前过滤结果中切换。添加歌曲或删除缺失歌曲后重新读取完整歌曲列表，并保留当前搜索词刷新可见结果。

如果正在播放的歌曲仍在过滤结果中，继续在列表中高亮；如果被当前搜索词过滤掉，歌曲继续播放，但列表不强行显示它。

## 组件与数据流

- `MusicPlayer` 增加完整歌曲列表字段，用于保存数据库读取结果。
- `MusicPlayer` 增加搜索输入框字段，用于读取当前搜索词。
- `reloadPlaylist()` 更新完整歌曲列表后应用当前搜索词。
- `applyPlaylist(...)` 继续负责把传入列表渲染成当前可见播放列表。
- 新增小型过滤方法，便于单元测试覆盖匹配规则。

## 错误处理

搜索过滤只处理内存列表，不产生新的数据库或文件错误。数据库读取、添加歌曲、删除缺失歌曲仍沿用现有异常处理和提示。

## 测试

新增或扩展单元测试覆盖：

- 空搜索词返回全部歌曲。
- 歌曲名匹配。
- 歌手匹配。
- 大小写不敏感。
- 空歌曲名或空歌手不会导致异常。

回归验证运行 `mvn test`。
